- 两个入口复用计算模块。首版暂不公开的内容不删除；共享模块修改必须明确影响范围，发布前补相关回归。
- 1.0 的修复、核心交互与手册整理优先；2.0 当前准备计划和清单。首版需要的小改进可纳入 1.0 候选稿，大项分开推进。

## 2. 按全局需求组织功能

现有 23 个开发入口按五类组织，后续首页仍先选择需求，不要求用户理解版本或模块名。

|需求类别|既有内容|下一步重点|
|---|---|---|
|事件预测|计数、日期、分组、常用/柔性模型、过程与参数不确定性、盲态组合、回测|先完善常用方法的稳定性和解释，再开放复杂模型；观察发生与中央报告口径分开|
|生存数据生成|单终点、条件续推、PFS/OS、多状态、访视/退出、协变量/中心/脆弱性|统一观察数据/真值契约、参数换算和示例；按用户研究问题进入相应生成流程|
|模拟研究与设计评价|固定/组序贯、NPH、独立队列/共享患者重估、多臂/两阶段|预设设计规则和分析方法；给出失败/未达标、MC 误差及方法适用范围|
|运行中研究|IA→Final、历史快照、条件预测、实际 IA 批量、历史推断、panel 拟合|冻结当前资料和原计划，阻断未来信息混用；限定正式检验与规划预测的适用条件|
|研究管理与规划|情景比较、配对、后台/续跑、研究库、候选搜索、反向校准|复用现有记录/导出流程；先把独立功能接通和复现，再考虑统一优化|

“既有内容”表示源码中有相应实现或限定分支，不能当作全部验证通过。详细范围沿用 `CAPABILITY_MATRIX.md` 和 `REMAINING_SCOPE.md`。

## 3. 2.0 分批顺序

|批次|优先范围|范围控制|交付条件|
|---|---|---|---|
|A 常用预测完善|Bootstrap、XPT/SAS7BDAT、常用扩展分布、事件驱动模拟、回测和少量情景|主要整理已有功能；先满足常见使用，再决定后验/模型组合开放|输入/输出/帮助/手册/导出闭环，专项验证后开放；必要时先作为 1.x 更新|
|B 设计与运行中研究|IA→Final、固定设计功效、NPH、标准组序贯、条件批量|按每次具体研究需求接入口；先完善已验证基础与已写入分支|冻结配置、原规则/当前资料与未来假设分开，独立参照及完整分母验证|
|C 联合与异质资料|PFS/OS、精确多状态、观察过程、协变量/分层/中心；常数 Markov panel 限定分支|从已实现、可解释和可识别的子模型开始，不承诺通用未知机制|数据契约、生成/拟合/续推分别验收；真值隔离和模型适用限制明确|
|D 高级设计与工具整合|共享患者适应、多臂/两阶段、搜索/确认、反向规划、研究库整合|保留已构造分支；复杂未完成项按实际需求立项，不自动变成发布阻塞|明确理论范围、错误率/覆盖或规划性质，专项验证；搜索和确认样本隔离|

A→D 为优先顺序，非要求一次全部实现。2.0 正式发布选择已经完成闭环并验证的功能集合，未成熟功能继续留在开发入口。新账号体系、持续平台试验、任意未知机制识别、全家族自动优化等暂不立项。

## 4. 从需求到发布的工作流程

1. **需求归类**：记录具体问题、研究起点（设计/运行中）、输入资料、所需结果，判断已有实现可复用还是需要新方法。
2. **范围冻结**：每批只选少量相关功能；明确模型、参数、数据结构、估计量/预测量和限制，记录现有代码状态。其余需求放入后续清单。
3. **开发闭环**：先计算与数据契约，再接入所需参数/结果、帮助、手册、示例和导出。只提交文件或空接口不标为功能完成。
4. **开发状态登记**：开发完成与验证完成分开。按用户安排可先写代码、随后集中验证；未经检查不进入正式发布入口。
5. **专项验证**：独立推导/数值参照、必要模拟校准、观察/真值隔离、单位与分母、核心回归、公式显示和真实导出复现。已有通过记录只覆盖原范围。
6. **候选版与发布**：更新实际开放清单和运行环境，在候选环境验证后发布对应版本，保留回退包。其余未验证研究分支继续隔离。
7. **使用反馈**：收集可复现的错误或具体研究需求，先修现有功能；决定下一批内容，不以功能数量作为完成比例。

每个功能用一行台账记录：需求/实现文件/数据契约/界面和帮助/手册/导出/验证状态/目标版本/限制。状态统一为“待规划、已有代码待整理、开发完成待验证、验证通过待发布、已发布”；理论条件未解决单独标记，不混入普通代码待办。
