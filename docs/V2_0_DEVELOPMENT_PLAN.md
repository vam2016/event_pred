## 2. 2.0首次发布范围

以三个核心任务为基础，优先整合以下已有能力：

|需求|首批边界|完成时用户得到什么|
|---|---|---|
|预测区间包含参数估计变化|ADTTE模式患者Bootstrap；先支持指数、Weibull、PWE及合并/已知两组|参数代入与Bootstrap清楚区分，失败轮次有记录，事件数及日期结果可重放|
|直接读取常用分析数据|CSV、XPT、SAS7BDAT共用ADTTE规范化；haven为可选依赖|格式、日期编码、终点和组别校验一致，导入失败可定位|
|比较常见分布假设|新增Log-normal、Log-logistic；其余分布保留研究入口|参数/数据两种模式、单位、参考曲线、拟合诊断、结果与导出一致|
|按累计事件数生成模拟截点|单终点事件驱动模拟；目标、最大窗口、并列事件与未达标状态显式记录|实际DCO、事件数、未达标比例及观察/真值/ADTTE分开输出|
|判断预测是否稳定|历史回测与少量预设情景对照|训练截点与后续观察严格分开，每情景保留配置、结果、误差及完整分母|

首批完成闭环并通过对应验收，形成`2.0.0-rc.1`；在目标环境通过后才正式发布`2.0.0`。若某项尚未成熟，可保留为开发功能并重新记录候选版实际范围，不为赶版本隐去失败或降低统计标准。

参数模式不凭空增加数据估计不确定性；Bootstrap逐点预测区间不称为同时置信带；情景对照不自动构成正式检验。公开入口继续先选研究问题，不一次开放全部23个入口。

1.0正式发布收尾列为独立待办，2.0可继续本地开发；正式2.0发布前同样需要目标环境验收。现有启动脚本仍启动核心入口，扩展入口需要独立指定；M4前明确新版默认入口和开放清单。

## 5. 每项功能的工作流程

1. **冻结需求**：写出场景、输入、统计目标、模型假设、允许范围及不支持的情况；登记工作项ID和源码范围。
2. **计算与数据契约**：复用已有引擎，先完成规范化/冻结配置/失败状态/结果对象。共享模块修改注明核心与扩展两侧的影响。
3. **用户闭环**：连接参数、帮助、图表、表格、手册、合成示例、配置/CSV/报告与复现脚本；仅有源码不能标完成。
4. **方法验收**：独立解析/数值参照，必要模拟校准；事先规定容差和MC误差规则。检查单位、随机种子、分母、未达标、拟合失败及观察/真值隔离。
5. **运行验收**：核心回归、新功能浏览器交互、窄屏/公式及实际下载文件重放；需要依赖时明确版本与安装边界。
6. **记录与候选交付**：状态、证据路径、源码提交、实际开放范围同步更新；通过的功能才进入候选入口。
7. **发布与反馈**：目标环境检查、版本和回退包、发布说明；优先修现有功能，再决定下一批。

状态采用“待开展、整理中、开发完成待验证、验证通过待发布、已发布”；另外单列“加载阻塞、理论/识别条件未解决”。负责人默认当前开发工作，不新增协作审批流程。可逆开发与修复直接推进；范围改变时更新计划和验收条件。

- 区分历史证据、本次重新执行和计划执行；旧文档中的端口/预览不视为当前服务存活证明。

- 扩展专项选用`NEXT_REVIEW.md`中与当前工作项有关的范围，不要求所有高级理论扩展一次验收。
- 扩展分支原工作流仅支持手动运行；M0已加入2.0分支push及PR自动解析/入口检查，远程Linux及Windows检查已通过。核心CI通过不代表扩展方法通过。
