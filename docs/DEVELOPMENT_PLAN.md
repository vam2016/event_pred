# EVENT / PRED 开发方案

目标是建立面向 OS/PFS 等事件驱动试验的 R Shiny 平台，把预测工具、假设比较与方法推导放在同一工作流中。代码托管于 `vam2016/event_pred`。界面中文优先，保留必要英文术语。

## 首版 v0.1：已实现的可运行基础

|模块|首版能力|边界|
|---|---|---|
|输入与状态|CSV、合成模板、截点验证、event/active/dropout|天为唯一单位，active 必须观察至截点，合并无协变量|
|事件模型|指数、Weibull、PWE、Log-normal、Log-logistic、KM+指数尾部|KM 尾部需显式设定；PWE 固定切点|
|未来过程|条件生存、恒定率 Poisson 入组、独立指数脱落、风险倍数、固定未来上报延迟|未来过程参数是情景，未联合估计；未处理历史未上报事件|
|不确定性|plug-in、受试者 bootstrap、指数/PWE Gamma 后验|不等于完整贝叶斯试验预测|
|模型组合|AIC 加权预测混合|固定权重、排除 KM，不称为 BMA|
|结果|事件曲线、逐点 95% 区间、目标日期、窗口内概率、模型拟合对比|保留未达标轮次；达标日期不依赖绘图网格|
|教学|条件生存实验室、模型公式、似然推导、模拟逻辑、来源与实现范围|专门模型标为规划中|
|导出|CSV、JSON 运行配置、Markdown 摘要|从成功运行快照导出，不包含上传数据原文|

首版是一项有测试的研究原型；还需下面的校准和外部验证后才适合作为正式项目操作预测依据。

## 第二阶段：数据层与验证优先

1. 日期输入与字段映射：随机化日、末次确认日、事件日、脱落日、上报日；自动识别单位并统一为天。保留“确认无事件至某日”和“截点日”的差异。
2. 同一试验多次 Data Cut 快照与历史回测；避免用截点之后信息拟合早期模型。允许对早期文件关联已知完整结果，用其评价预测。
3. 合并/按组/分层分析及授权范围提示；默认盲态合并。保持未来组别分配与随机化比例一致，不能把盲态模型的潜在类别解释为真实分组。
4. 入组与脱落模型：手动情景、数据估计、Poisson-Gamma、分段率、NHPP、中心启动；停止入组、样本量上限和中心异质性。
5. 验证矩阵：指数、单调与非单调风险、延迟效应、混合、治愈、稀疏事件、慢入组、高脱落、上报滞后。比较偏差、MAE/RMSE、日期区间覆盖率/宽度、事件数覆盖率、概率校准/Brier score、Monte Carlo 误差与运行时间。
6. 测试零事件/少事件、切点边界、日期闰年、窗口内不达标、理论不可达标、bootstrap 失败、极端参数、会话隔离、输入改变后结果快照一致性。
7. 支持启动前规划：由设计假设生成全试验，明确区分“无当前数据的设计模拟”与“基于当前数据的条件预测”。

完成判据：历史截点无信息泄漏；报告能追溯配置、数据摘要、种子、软件版本与失败；在预设模拟矩阵中公开校准结果，不以单一拟合优度替代预测性能。

## 第三阶段：贝叶斯与模型不确定性

- 完整贝叶斯 Weibull/PWE，入组/脱落/事件联合后验，历史信息借用和先验敏感性。
- MCMC 的 R-hat、bulk/tail ESS、链迹与失败策略；先验与后验预测检查。
- 回测权重/stacking，以及指定模型先验和证据方法的 BMA。与当前 AIC 混合分开命名。
- 模型不确定性和尾部情景作为独立维度，输出对达标日期的敏感性。
- 事件发生与上报双时钟，截点前未上报事件和延迟分布模型；不把后台上报积压患者错误当作已知无事件。

完成判据：参数恢复、条件预测公式与基准软件对比、链收敛、先验敏感性及区间覆盖率均有可审查结果。

## 第四阶段：专门模型

|模型|实现路径|验收重点|
|---|---|---|
|盲态混合 / BayesPET|核对全文/作者代码后实现 Weibull 混合，已知随机化比例|标签交换、混合可识别性、先验影响、盲态泄露|
|治愈与混合治愈|拟合治愈比例与未治愈者生存；每轮保留永不发生事件|成熟度不足的识别问题；目标永不达到概率|
|广义 Gamma、Gompertz、灵活样条|适配成熟 R 库，并锁定参数化与尾部规则|与库基准对比、单调性、尾部数值稳定性|
|变化点/延迟治疗效应|已知变化点情景与未知变化点模型分开|风险变化不确定性、时间轴定义|
|协变量、中心、分层|共享接口，明确未来患者协变量生成方式|外推人群与建模人群匹配、缺失和样本量|
|PFS 辅助 OS / 多状态|状态转移生成器、Markov/半 Markov、直接死亡路径|状态路径合法、转移依赖、OS 联合校准|
|机器学习辅助|作为可选研究模块，先确定外推和校准方法|时间泄漏、外部校准、可解释性|

## 平台结构与交互

导航为“预测工作台 → 数据与拟合 → 条件生存实验室 → 方法与推导 → 开发路线”。工作台的核心是一条**日历时间事件成熟轨迹**，配合目标事件水平线、达标日期表和累计达标概率。条件实验室使用个体随访轴，帮助理解“已随访 a 天后继续预测”的含义。

视觉系统：深海蓝 `#142d46` 用于文字，青蓝 `#126c86` 用于操作和主模型，浅蓝灰 `#f3f7fb` 用于工作背景，白色 `#ffffff` 用于阅读区域；紫/琥珀/青绿用于模型区分。采用系统字体与可访问焦点、可滚动表格和响应式布局。

每个预测结果关联一次运行快照。修改输入不会静默重写已完成结果；成功运行才替换快照。模型失败和排除轮次显式呈现。方法库每章均包含“预测问题 → 假设 → 似然 → 条件模拟 → 外推 → 不确定性 → 失效场景 → 实现状态 → 文献”。

## 架构与部署

计算核心与 Shiny 展示分开：`R/models.R` 定义拟合、生存、累计风险、逆函数与参数抽样；`R/forecast.R` 负责当前队列、未来入组、脱落和试验级预测。新增模型必须遵循同一接口，或明确使用专门状态生成器。

首版依赖 Shiny、bslib、survival、ggplot2、plotly、DT、jsonlite 和 scales；已提供安装脚本、容器配置与检查脚本。后续将添加依赖锁定、后台任务/取消、大模拟缓存、数据版本化及自动验证工作流。

GitHub 托管源码。**GitHub Pages 无法运行需要 R 服务端的 Shiny**；实际托管可选 shinyapps.io、Posit Connect 或有 R/Shiny Server 的服务器。首版先本地运行，未创建收费托管或公开数据服务。
