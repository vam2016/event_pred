### 首版 CSV 格式

|字段|定义|示例|
|---|---|---|
|`id`|非空、唯一的受试者标识|S001|
|`entry`|从研究起点至入组的天数|20|
|`time`|从入组至已观察事件或删失的天数，必须大于 0|520|
|`status`|`event`、`active` 或 `dropout`|active|

首版统一使用**天**。研究起点日期用于将日数映射为日历日期，预测图使用日历时间，生存拟合图使用个体随访时间。

- `event`：已观察、已确认的目标事件。发生时间为 `entry + time`，之后固定。
- `active`：持续观察到本次截点，满足 `entry + time = cut`，之后可以继续贡献目标事件。
- `dropout`：观察至 `time` 后永久失访/退出目标终点观察，不再贡献未来可观察事件。模型拟合时作为右删失。

疾病进展后停止用药不必然是 OS 的 dropout；请按目标终点的实际随访状态编码。PFS 的末次充分肿瘤评估早于截点时，不能直接把其当作持续观察到截点的 active；首版会拒绝这种数据，后续将加入评估间隔及信息滞后模型。

首版要求至少 3 名受试者、2 个事件，最多 5,000 名受试者。不接受缺失或超过截点的观察时间。额外字段可存在，但不会用于模型拟合。

默认为**合并、无协变量预测**。首版没有组别、分层、中心或多状态拟合；这些在开发路线中单列。

所有模板均为合成数据。应用不会把上传文件提交到 GitHub；运行数据保留在本次 Shiny 会话中。部署服务器仍将处理上传的数据，因此生产部署需按实际使用环境配置访问权限。
